## Agent 실행 흐름 분석

음성 또는 텍스트 기반 AI 상호 작용을 개선하려면 각 대화 턴에서 시스템이 어떤 과정을 거치는지 파악하는 것이 중요합니다. Daisybell은 **비개발자**(제품 관리자, 구축 전문가, 테스트 엔지니어, 기업 고객)을 위해 **Agent Analysis Trace (대화 경로 분석)** 기능을 제공합니다. 누구나 시각화된 진단 화면을 통해 시스템의 주요 실행 과정을 분석하고 상호작용 지연이나 오류가 발생한 지점을 빠르게 찾아 Agent의 대화 품질을 개선할 수 있습니다.

---

### 1. 기능과 접근 방법

- **제품 개요:** 대화 흐름에서 시스템 실행 기록을 상세히 분석하는 기능입니다. 각 인터랙션의 내부 상태를 확인해 업무 병목이나 장애 지점을 찾도록 돕습니다.
- **접근 경로**: Agent Detail의 대화 기록 페이지에서 대화  기록에 있는 Agent 발화 내용 아래의 **Latency (소요 시간)** 레이블을 클릭하면 화면 오른쪽에 분석 패널이 열립니다.

### 2. 전체 진단 지표 (Global Metrics)

Analysis Trace를 열면 상단 대시보드에 해당 대화 턴의 핵심 지표가 표시되어 기본 성능 상태를 파악할 수 있습니다.

![](/images/ko/agent-operator/alpha/img-IigAbBDQgoaUvixqRhfjGjrLpid.png)

- **시작 시간 (Start Time)**: 해당 대화 턴이 시작된 정확한 시각을 기록합니다. 형식: `YYYY-MM-DD HH:MM:SS`.
- **전체 지연 시간 (Total Latency)**: **사용자의 발화가 끝난 시점부터 AI가 발화를 시작한 시점**까지의 전체 시간으로 정의합니다(단위: 밀리초/ms). 성능 상태를 직관적으로 확인할 수 있도록 지연 시간에 색상 표시를 적용합니다. 값은 10ms 단위로 올림 처리됩니다.

  - **지연 시간**  : **노란색**
  - **지연 시간**  : **빨간색**
- **Token 사용량 (Token Consumption)**: 현재 턴에서 모든 대규모 언어 모델(LLM) 호출에 사용된 Token의 총합($\sum\text{LLM}$).
- **처리 상태 (Status)**: 현재 턴의 최종 처리 상태를 표시합니다. 상태는 **성공 (Success)** 또는 **실패 (Failed)**입니다.

### 3. 프로세스 타임라인 (Processes Timeline)
지연 시간의 구성을 한눈에 볼 수 있도록 분석 패널 왼쪽에 여러 레인으로 구성된 타임라인을 표시합니다. 시스템 처리 흐름의 핵심 서비스 프로세스는 실행 순서에 따라 위에서 아래로 배치됩니다.
- **시각화된 지연 시간 막대**: 각 프로세스는 실제 시작 및 종료 시각에 맞춰 정렬된 색상 막대로 표시됩니다.
- **핵심 경로 식별**타임라인에서 겹치거나 교차하거나 연결된 지연 시간 막대가 가장 긴 연속 경로를 형성합니다. 이 경로가 전체 Latency 지표에 해당합니다.
- T:숫자는 현재 프로세스에서 사용된 Token 수를 나타냅니다.

### 4. 핵심 서비스 구성 요소 상세 분석 (Component Breakdown)

오른쪽 패널은 서비스 프로세스별 상세 콘솔입니다. 펼쳐서 음성 입력부터 음성 출력까지 전체 스택 로그를 확인할 수 있습니다.

#### 4.1 음성 인식 및 발화 종료 판단 (ASR & VAD)

음성 수집부터 텍스트 인식까지의 전 과정을 통합해 보여줍니다. 전체 지연 시간은 다음 세 영역으로 구성됩니다.

- **음성 활동 감지 (VAD)**: 사용자의 실제 발화 종료 시각(Back Endpoint time)과 발화 시간(Actual duration)을 표시합니다.
- **음성 인식 (ASR)**: ASR 모델의 인식 소요 시간(Duration)과 최종 변환 텍스트(Output)를 표시합니다.
- **발화 종료 판단 (Completeness Detection)**: 모델 호출 시각(Model Call Time), 모델 응답 시각(Model Return Time), 판단에 적용한 지연 시간 가중치를 정확하게 기록해 사용자의 발화가 끝났는지 시스템이 올바르게 판단하도록 합니다.

  ![](/images/ko/agent-operator/alpha/img-IdTpbD1D6oKYcPx3cQojHXb3pcg.png)

#### 4.2  LLM 모델 처리  (LLM Module)

AI의 추론 과정을 핵심 실행 데이터 및 컨텍스트 흐름과 함께 보여줍니다.

- **실행 파라미터**: 해당 턴에서 호출한 모델 이름(예: GPT-4o), LLM 프로세스 소요 시간, 요청 한 건의 Token 사용량을 표시합니다.
- 입력:
- 출력: “Content”에 포함된 내용을 표시합니다.

![](/images/ko/agent-operator/alpha/img-TcXTb7Rgdo122gxXwbKj1jTzp3c.png)

#### 4.3 도구 호출 (Tool Calling)

Agent가 외부 시스템을 호출하거나 특정 지시를 실행한 흐름을 추적합니다. 기본 제공 Function과 사용자 정의 Function 등 여러 유형의 실행 상태를 추적합니다.

- **모든 유형 지원**: 지식 검색(Knowledge query), 전화 전환(Call Transfer, 신·구 버전 로직 포함), 지시 모드 전환(Instruction mode), 통화 종료(Hang up), 언어 전환(Language switching), 업무 사용자 정의 인터페이스(Customize) 등 각종 플러그인 호출 기록을 자세히 확인할 수 있습니다.
- **구조화된 로그**: 각 Tool Call에서 호출된 Function 이름(Function_name), 처리 시간, 표준 JSON 요청·응답 메시지(입력 파라미터 및 반환 결과)를 표시합니다.

  ![](/images/ko/agent-operator/alpha/img-BY0ZbYGU1o9vkgxEnJKjGoLepbc.png)

#### 4.4 음성 합성 출력 (TTS Module)

인터랙션 흐름의 마지막 단계로, 텍스트 음성 변환의 최종 실행 상태를 보여줍니다.

- **성능 추적**: TTS 모델에 요청을 보낸 시점부터 시스템이 첫 오디오 패킷(First Wave Chunk)을 수신한 시점까지의 실제 합성 시간을 기록합니다.
- **텍스트 검증**: 음성으로 변환한 원본 입력 텍스트(Input Text)를 표시해 안내 내용이 정확한지 확인할 수 있습니다.

![](/images/ko/agent-operator/alpha/img-Bj0ubQNYTomKM1xPwdZjOBRHpxe.png)
