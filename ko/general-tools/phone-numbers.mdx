## 전화번호 및 SIP 회선 설정

> 이 문서는 Daisybell Agent Lab에서 AI Voice Agent용 전화번호(Phone Numbers)를 관리하고 설정하는 방법을 안내합니다. SIP Trunk 발신·수신 회선을 설정해 고객의 통신사 회선과 음성 Agent를 원활하게 연결하고, 안정적이며 지연 시간이 짧은 양방향 실시간 음성 인터랙션을 구현할 수 있습니다.

---

### 개요(Overview)

Phone Numbers 모듈은 기업용 SIP 회선 연결과 통합 수명 주기 관리를 제공합니다. 아웃바운드 Agent 전용 발신 경로를 설정하거나 인바운드 Agent에 공개 회선을 연결하는 등, 이 모듈에서 자동 설정과 동시 통화 할당량을 관리할 수 있습니다.

<callout emoji="💡">
**비등록 방식의 피어 SIP Trunk를 지원하며, DTMF는 RFC4733(RFC2833), 오디오 코덱은 G.711 및 G.722를 지원합니다.**
</callout>

![](/images/ko/general-tools/phone-numbers/img-CI7nbBZzMoKXW3xahIGj5FnVpfg.png)

#### 주요 설정

- **양방향 회선 지원:** 인바운드(Inbound Numbers)와 아웃바운드(Outbound Numbers) 회선을 각각 관리합니다.
- **회선 동시 통화 제어:** 회선별로 발신 전용 동시 통화 수(Outbound Concurrency)와 전환 전용 동시 통화 수(Transfer Concurrency)를 설정할 수 있습니다.
- **보안 전송 및 인증:** SIP 인증(Digest Auth), 시그널링 암호화(TLS), 미디어 스트림 암호화(SRTP / DTLS-SRTP)를 기본 지원합니다.
- **보안 보호:** 인바운드 회선은 CIDR/IPv4 기반 발신지 IP 허용 목록을 검증합니다. 사용 중인 회선에는 실수로 삭제하거나 비활성화하지 않도록 보호 기능이 적용됩니다.

---

#### 회선 동시 통화 수와 실제 회선 용량의 차이

- **플랫폼 동시 통화 제한(Platform Concurrency Limit):** Agent Lab 화면에서 설정하는 `Call Concurrency`(발신 전용 및 전환 전용 동시 통화 수 포함)는**플랫폼의 보안 트래픽 제어 및 업무 할당량 제한**입니다. 이 값은 Daisybell 플랫폼이 해당 번호에서 동시에 연결할 수 있는 최대 통화 세션 수를 결정합니다.
- **통신사 회선의 실제 용량(Carrier Physical Capacity):** 회선의 실제 동시 통화 용량은 계약한 통신사/SIP Trunk 사업자(Provider)의 게이트웨이 대역폭과 채널 용량에 따라 달라집니다. 플랫폼 동시 통화 설정이 통신사 채널 용량을 초과하면 초과한 호출이 통신사 게이트웨이에서 거부될 수 있습니다(예: `SIP 503 Service Unavailable`).

### 전화번호 상태

시스템의 각 전화번호 회선에는 명확한 상태가 표시됩니다.

| 회선 상태(`Status`) | 정의 | 제한 및 동작 |
|-|-|-|
| `Unused` (미사용) | 번호가 등록되고 설정을 마쳤지만 어떤 AI Agent에도 연결되지 않은 상태입니다. | 언제든지 편집, 비활성화 또는 삭제할 수 있습니다. |
| `In Use` (사용 중) | 번호가 특정 아웃바운드 작업, 인바운드 응대 또는 상담원 전환 정책에 연결된 상태입니다. | 삭제하거나 비활성화할 수 없습니다. |
| `Disabled` (비활성화됨) | 회선을 수동으로 비활성화해 모든 통화 라우팅을 중단한 상태입니다. | 모든 Agent의 회선 선택 목록에서 숨겨지며 통화 번호로 선택할 수 없습니다. |

### 발신 번호 설정(Outbound Numbers)

<grid>
<column width-ratio="0.500000">
발신 번호는 AI Agent가 직접 시작하는 아웃바운드 작업과 통화 중 상담원에게 전환하는 데 사용됩니다.
#### 절차
1. **관리 페이지로 이동**`Tools` > `Phone Numbers`에서 `Outbound Numbers` 탭을 선택합니다.
2. **설정 양식 열기:** 페이지 오른쪽 위의 `+ Add New` 버튼을 클릭합니다.
3. **번호 입력:** 대상 전화번호를 입력합니다(숫자만 입력하거나 E.164 형식 사용).
4. **종료 게이트웨이(Termination URI) 지정:** 통신사 SIP 서버의 도메인 또는 IP와 포트를 설정합니다.
5. **전송 프로토콜 및 미디어 암호화(Transport & Encryption) 설정:**

   - **전송 방식(`Transport`):** 통신사 게이트웨이 규격에 따라 시그널링 수신 프로토콜(`UDP` / `TCP` / `TLS`)을 선택합니다.
   - **암호화 방식(`Encryption`):** 회선 보안 등급에 따라 미디어 암호화 프로토콜(`None` / `SRTP` / `DTLS-SRTP`)을 선택합니다.
6. **동시 통화 정책:** 동시 통화 할당량을 지정합니다. 발신 전용 및 전환 전용 동시 통화 수를 설정할 수 있습니다.
7. **확인 및 저장:** 설정을 확인한 후 `Add Number` 를 클릭해 회선을 등록합니다.
</column>

#### 매개변수 사양 안내

| 매개변수 | 필수 | 형식 | 설명 |
|-|-|-|-|
| `Phone Number` | 예 | 문자열(숫자만 입력 또는 E.164 형식) | 실제 발신에 사용할 발신 번호입니다(E.164 형식, 공백 및 특수 문자 금지). |
| `Termination URI / Address` | 예 | `도메인:포트` 또는 `IP:포트` | 통신사에서 제공하는 SIP 발신 게이트웨이 주소입니다(예: `sip.example.com:5060`). |
| `Encryption` | 예 | 단일 선택:`None` / `SRTP` / `DTLS-SRTP` | 미디어 스트림 전송 암호화 프로토콜입니다. 기본값은 `None`입니다. |
| `Transport` | 예 | 단일 선택:`UDP` / `TCP` / `TLS` | SIP 시그널링 전송 계층 프로토콜입니다. 기본값은 `UDP`입니다. |
| `SIP Authentication` | 아니요 | 복합 객체(`Username`, `Password`) | 통신사가 요구하는 SIP 등록/호출 인증 정보입니다. 저장한 비밀번호는 평문으로 확인할 수 없습니다. |
| `Dedicated Outbound Concurrency` | 예 | 정수(`0–1000`) | 해당 번호에서 일반 아웃바운드 통화를 시작할 때 적용되는 최대 동시 통화 수입니다. 기본값은 `10`입니다. |
| `Dedicated Transfer Concurrency` | 예 | 정수(`0 - 1000`) | 통화 전환이 발생할 때 해당 번호에 적용되는 최대 동시 통화 수입니다. 기본값은 `0`입니다. |
| `Show Main Caller ID For Transferred Calls` | 아니요 | 불리언(스위치, 기본값 꺼짐) | 이 기능을 켜면 통화를 제3자 또는 상담원에게 전환할 때 최초 발신 번호를 계속 전달합니다. |

> **⚠️ 주의:** 이 옵션을 켜기 전에 `Show Main Caller ID For Transferred Calls` 통신사 회선이 외부 발신 번호 전달(CLI Pass-through)을 지원하는지 반드시 확인하세요. 지원하지 않으면 게이트웨이에서 전환 통화를 거부할 수 있습니다.

### 인바운드 번호 설정(Inbound Numbers)

<grid>
<column width-ratio="0.500000">
인바운드 번호는 외부 통신망에서 오는 호출을 수신해 연결된 Daisybell Voice Agent로 자동 라우팅하는 데 사용됩니다.
#### 절차
1. **인바운드 목록으로 전환:**`Tools` > `Phone Numbers`를 클릭한 다음 `Inbound Numbers` 탭을 선택합니다.
2. **인바운드 설정 추가:** 오른쪽 위의 `+ Add New` 버튼을 클릭해 설정 양식을 엽니다.
3. **번호 입력:** 대상 전화번호를 입력합니다(숫자만 입력하거나 E.164 형식 사용).
4. **보안 허용 목록(White List) 설정:** 플랫폼으로 SIP 인바운드 트래픽을 보낼 수 있도록 허용할 통신사 게이트웨이 IP 또는 CIDR 네트워크를 추가합니다.
5. **전송 프로토콜 및 미디어 암호화(Transport & Encryption) 설정:**

   - **전송 방식(`Transport`):** 통신사 게이트웨이 규격에 따라 시그널링 수신 프로토콜(`UDP` / `TCP` / `TLS`)을 선택합니다.
   - **암호화 방식(`Encryption`):** 회선 보안 등급에 따라 미디어 암호화 프로토콜(`None` / `SRTP` / `DTLS-SRTP`)을 선택합니다.
6. **동시 통화 할당량:** 해당 번호에서 허용할 최대 인바운드 동시 통화 수를 지정합니다.
7. **검증 및 완료:** 허용 목록 형식 검증을 통과했는지 확인한 후 `Add Number`을 클릭합니다.
</column>

#### 매개변수 사양 안내

| 매개변수 | 필수 | 형식 | 설명 |
|-|-|-|-|
| `Phone Number` | 예 | 문자열(숫자만 입력 또는 E.164 형식) | 인바운드 번호입니다(E.164 형식, 공백 및 특수 문자 금지). |
| `White List Address` | 예 | IPv4 주소 또는 CIDR 블록 | SIP INVITE를 전송할 수 있는 통신사 게이트웨이 허용 목록입니다. 여러 항목을 설정할 수 있습니다. |
| `Encryption` | 예 | 단일 선택:`None` / `SRTP` / `DTLS-SRTP` | 미디어 암호화 정책입니다. |
| `Transport` | 예 | 단일 선택:`UDP` / `TCP` / `TLS` | 인바운드 시그널링을 수신하는 프로토콜입니다. |
| `Total Call Concurrency` | 예 | 정수(`1–1000`) | 해당 인바운드 번호에서 동시에 연결할 수 있는 최대 통화 수입니다. 기본값은 `10`입니다. |

#### IP 허용 목록 검증 규칙

시스템은 `White List Address` 에 대해 형식과 보안 여부를 실시간으로 검증합니다.

- **검증 통과(`Validated`):** 표준에 맞는 IPv4 또는 CIDR(예: `123.24.56.78` 또는 `123.24.56.78/20`)를 입력하면 초록색 검증 성공 상태가 표시됩니다.
- **형식 오류(`Invalid IP Format`):** 잘못된 문자가 포함되거나 허용 범위를 벗어난 IP를 입력하면(예: 프로덕션 허용 목록에 `0.0.0.0` 을 입력하는 경우) 제출이 차단되고 오류가 빨간색으로 강조 표시됩니다.
- **중복 제한(`Duplicate IP`):** 같은 번호 설정에 중복된 IP 또는 네트워크를 추가할 수 없습니다.

### 회선 관리 및 작업(Line Actions)

번호 목록 오른쪽의 `Actions` 작업 메뉴에서 다음과 같은 유지 관리 작업을 수행할 수 있습니다.

#### 1. 상세 보기(Details)

상세 정보 모달을 열면 읽기 전용 시스템 메타데이터와 네트워크 매개변수를 확인할 수 있습니다. 여기에는 `SIP Line ID`(시스템 고유 식별자), 생성 시간(`Date Added`), 현재 적용 중인 설정 및 연결된 Agent 이름이 포함됩니다.

#### 2. 회선 편집(Edit)

- **변경할 수 없는 필드:** 시스템에서 할당한 `SIP Line ID` 은 전체 시스템에서 고유하며 생성 후 변경할 수 없습니다.
- **회선 사용 잠금:** 회선 상태가 `In Use`인 경우 네트워크 매개변수를 수정하고 저장을 클릭하면 시스템이 재확인 창을 표시합니다.



#### 3. 활성화 및 비활성화(Enable / Disable)

- **비활성화 제한:**`In Use` 상태의 회선은 **직접 비활성화할 수 없습니다**. 먼저 연결된 Agent에서 번호 연결을 해제하거나 다른 번호로 바꾸세요.
- **비활성화 영향:** 회선을 비활성화하면 사용할 수 없으며 모든 Agent 설정의 선택 목록에서도 해당 번호가 숨겨집니다.
- **활성화 절차:**`Disabled` 상태의 회선은 작업 메뉴에서 `Enable` 를 선택하면 다시 사용할 수 있고 미사용 회선 목록으로 돌아갑니다.

#### 4. 삭제(Delete)

- **차단 규칙:**`In Use` 상태인 회선은 화면에서 `Delete` 작업이 비활성화되고 백엔드 API에서도 강력한 검증으로 삭제를 차단합니다.
- **삭제 전 안내:**`Unused` 또는 `Disabled` 상태의 회선만 삭제할 수 있습니다. 확인 창에 안내 메시지가 표시됩니다.

### 계정 권한(Role-Based Access Control):

| 플랫폼 역할(`Role`) | 페이지 보기(`View`) | 생성/편집/활성화/비활성화/삭제(`Manage`) |
|-|-|-|
| **Admin** (기업 관리자) | 접근 가능 | 사용 가능 |
| **Sub-user** (서브 계정/팀 구성원) | 접근 권한 없음(화면에 표시되지 않음) | 권한 없음 |

### 자주 묻는 질문(Troubleshooting)



**Q1: Agent 편집 페이지에서 방금 추가한 전화번호를 선택할 수 없는 이유는 무엇인가요?**

> `Phone Numbers` 목록에서 해당 번호의 상태를 확인하세요. 상태가 `Disabled`이면 해당 번호가 Agent 회선 드롭다운 목록에서 자동으로 숨겨집니다. 인바운드 번호라면 해당 유형이 Agent의 통화 모드(Inbound)와 일치하는지 확인하세요.



**Q2: 통신사가 인바운드 통화를 거부하거나 403 Forbidden 오류가 발생하는 이유는 무엇인가요?**

> `White List Address` 설정을 확인하세요. SIP INVITE를 전송하는 통신사 SBC/게이트웨이 IP가 허용 목록 또는 CIDR 네트워크에 빠짐없이 포함되어 있는지 확인합니다.



**Q3: 유휴 테스트 번호를 삭제할 수 없는 이유는 무엇인가요?**

> 해당 번호가 Agent의 예비 전환 번호(Transfer Line)로 설정되어 있는지 확인하세요. 플랫폼의 활성 규칙에서 해당 번호를 참조하고 있으면 시스템은 회선 상태를 `In Use` 로 판단해 삭제 요청을 자동으로 차단합니다.



**Q4: Agent 설정 페이지의 ‘회선 선택’ 드롭다운에서 새로 추가한 번호를 찾을 수 없는 이유는 무엇인가요?**

> - 번호 상태가 `Disabled`인지 확인하세요. 비활성화된 회선은 시스템에서 자동으로 필터링되어 표시되지 않습니다.
> - 번호 유형도 확인하세요. 예를 들어 인바운드 Agent에는 `Inbound Numbers` 유형을 연결해야 합니다.



**Q5: 번호 삭제 버튼이 비활성화되어 클릭할 수 없는 이유는 무엇인가요?**

> - 해당 번호의 현재 상태는 `In Use` 입니다. 아웃바운드 작업의 발신 회선, 인바운드 대표 번호 또는 통화 전환 대상 회선으로 지정되었는지 확인하세요. 모든 연결을 해제한 후 삭제할 수 있습니다.



**Q6: 통화가 동시 통화 한도에 도달하면 시스템은 어떻게 처리하나요?**

> - 플랫폼에서 설정한 `Call Concurrency` 에 도달하면 플랫폼이 자동으로 트래픽 제한을 적용합니다. 동시 통화 수를 높이려면 통신사 게이트웨이의 실제 처리 용량도 함께 확인한 뒤 이 페이지에서 설정을 늘리세요.
