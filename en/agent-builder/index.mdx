## Overview

The Agent Builder in Daisybell Agent Lab is a structured entry point for building agents for telephony and conversational use cases. It is designed for enterprise agent builders, BPO providers, and customer delivery teams.

A production-ready agent often involves identity, language, voice, conversation flow, business knowledge, data fields, variables, and tool calls. Agent Builder brings these elements into one configuration flow. First, define the agent's basic information and business entry point. Then configure languages, voice, telephony resources, concurrency, and other runtime conditions. Next, use Script to organize conversational behavior, and complete the business workflow with Skills, Tools, Knowledge, Fields, and Variables. This gives business identity, conversation strategy, actions, and data records a clear place in the configuration, so teams can maintain an agent by module instead of accumulating all logic in one difficult-to-manage prompt.

Agent Builder focuses on the real-world constraints of telephony operations. Builders can choose a primary and secondary language as needed, configure the voice capabilities for each language, and account for resource limits such as telephone lines, outbound calls, and transfers. Organize conversation rules with Script and reusable Skills. Configure Tools and Functions for actions such as lookups, call transfers, knowledge retrieval, language switching, call termination, and custom business operations. Tool inputs, outputs, and variable mappings can be linked to agent fields, allowing information such as order numbers, customer tiers, processing outcomes, and transfer status to be recorded in a structured way.

Knowledge is not simply uploaded and handed to a model. Agent Builder works with knowledge-base file management, review of parsing results, and Script associations so teams can curate product policies, after-sales terms, and other business materials as maintainable knowledge assets, then specify which business conversations can use them. For scenarios involving identity verification, one-time password entry, or sensitive information, tool and variable configuration can represent business boundaries such as validation, retries, failure handling, and data protection. This allows rules such as “verify first, then proceed” to be reflected in the agent's runtime configuration.

Agent Builder can therefore take an agent from a demonstration prototype to a deliverable configuration that meets enterprise business requirements. It helps teams define what the agent does, what information it relies on, when it calls tools, how it records results, and how it handles a business conversation within the constraints of telephony, language, knowledge, and data. With a unified, structured configuration, organizations can build maintainable agents around specific business needs and continue managing their rules, knowledge, actions, and records throughout delivery.
