### 2. Configure Alert Recipients

You can set a separate alert email address for each Agent in the workspace. This feature supports the multilingual interface.

**Configuration Steps:**

1. Sign in to the workspace and open the relevant Agent's **Agent Profile**.
2. Click **Settings**.
3. From the drop-down menu, select **Agent Exception Alert**.

![](/images/en/agent-operator/not-currently-in-use-requires-iteration/img-IhkabfTFooZaacxSNJejfMkdpxc.png)

1. In the dialog, enter an email address for alert notifications and click **Add**.

![](/images/en/agent-operator/not-currently-in-use-requires-iteration/img-BV1UbVgjmo83wJx9sjPjHvfopHg.png)

**Configuration Details and Limits:**

- **Capacity Limit**: Each Agent can have up to **10** recipient email addresses. Once this limit is reached, the Add button is disabled.
- **Manage the List**: View added email addresses in the list. Click the delete icon (🗑️) next to an address to remove a recipient who no longer needs notifications.
- Only administrator and OP accounts can configure this setting. Sub-accounts cannot change it.

### 3. Alert Emails

When an exception occurs, designated recipients receive a standardized system email with key information to help them identify the issue.

- **Sender**: By default, email is sent from `noreply@daisybell.ai` (enterprise OEM sender customization is supported).
- **Email Subject**:`[Exception] {Daisybell} AI Agent Runtime Status Alert`

![](/images/en/agent-operator/not-currently-in-use-requires-iteration/img-XSDkb3RNQoOsrsxk2V9jR1oOpTf.png)

**The email body contains the following key fields:**

- **Workspace**: Name or ID of the workspace where the exception occurred.
- **Agent**: Name of the Agent that encountered the exception.
- **Exception Type**: Identifies the failure category, such as Timeout or Connection Error.
- **Severity**: Severity level of the exception, such as High.
- **Occurrence Time**: Exact time when the exception occurred. The system automatically uses the business time zone for the current region (for example, UTC+8 for Hong Kong and UTC+9 for Japan and South Korea) to support accurate auditing and time tracking.
