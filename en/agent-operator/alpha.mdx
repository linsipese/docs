## Agent Execution Trace Analysis

When improving AI voice or text interactions, it is essential to understand the system's execution path behind each turn. Daisybell's Agent Analysis Trace feature is designed for**non-engineering users** (including product managers, delivery specialists, test engineers, and enterprise customers) and provides **Agent Analysis Trace** for in-depth analysis. Its visual, no-code diagnostics help you examine key system processes and quickly locate sources of interaction latency or errors, improving the Agent's conversational performance.

---

### 1. Purpose and Access

- **Purpose**: Inspect system execution traces in a conversation flow. By examining the internal state of each interaction, business teams can identify system bottlenecks and failures.
- **Access**: On the Agent details page, open Conversation Record and click the **Latency** tag beneath any Agent message bubble. A full analysis drawer opens on the right side of the page.

### 2. Global Metrics

When you open Analysis Trace, the dashboard at the top first shows key global metrics for the current turn, giving you an initial performance snapshot:

![](/images/en/agent-operator/alpha/img-2.png)

- **Start Time**: The precise time when the turn was triggered, in the format `YYYY-MM-DD HH:MM:SS`.
- **Total Latency**: Defined as **the interval from the end of the user's speech to when the AI starts speaking**, measured in milliseconds (ms). A health color indicator provides a visual performance warning. Latency values are rounded up:

  - **Latency** $\ge 2000\text{ms}$: displayed in **yellow**
  - **Latency** $\ge 3000\text{ms}$: displayed in **red**
- **Token Consumption**: Total tokens consumed by all large language model (LLM) calls in the current turn ($\sum\text{LLM}$).
- **Status**: The final processing status of the turn, marked as **Success** or **Failed**.

![](/images/en/agent-operator/alpha/img-3.png)

### 3. Process Timeline Swimlanes
To make the components of latency easy to understand, the left side of the analysis drawer provides a multi-lane timeline. Core services in the system processing path are arranged vertically in execution order:
- **Visual Latency Bars**: Each process is shown as a colored duration bar whose start and end align with the actual timestamps.
- **Identify the Critical Path**: Overlapping, interleaved, or sequential duration bars combine to form the longest continuous path. This is the global latency shown in the analysis.
- T: followed by a number indicates the tokens consumed by the current process.

### 4. Core Service Component Breakdown

The right side of the drawer provides a detailed console for each service process. Expand the entries to inspect the full-stack logs from voice input through voice output:

#### 4.1 Speech Recognition and Utterance Completeness (ASR and VAD)

This section covers the process from audio capture to text conversion. Total latency is composed of the following three parts:

- **Voice Activity Detection (VAD)**: Shows the actual endpoint time for the user's speech (Back Endpoint time) and the duration of the user's speech (Actual duration).
- **Automatic Speech Recognition (ASR)**: Shows the ASR model's recognition duration and the final transcribed text output.
- **Utterance Completeness Detection**: Records the model call time, model return time, and latency weight used for the determination, so the system can accurately decide whether the user has finished speaking.

  ![](/images/en/agent-operator/alpha/img-5.png)

#### 4.2 LLM Processing (LLM Module)

Shows the AI decision-making process, including core execution data and context flow:

- **Execution Parameters**: Shows the model used for the current turn (such as GPT-4o), LLM process duration, and tokens consumed by the request.
- Input:
- Output: Displays the content in “Content”.

![](/images/en/agent-operator/alpha/img-6.png)

#### 4.3 Tool Calling

Track actions where the Agent invokes external systems or executes specific instructions. The system supports execution status tracking for multiple built-in and custom Functions:

- **All Function Types**: Logs plugin calls, including Knowledge query, Call Transfer (both legacy and current flows), Instruction mode, Hang up, Language switching, and custom business interfaces (Customize).
- **Structured Logs**: Shows the Function name, service duration, and standard JSON request and response messages (input parameters and returned results) for each Tool Call.

  ![](/images/en/agent-operator/alpha/img-7.png)

#### 4.4 Speech Synthesis Output (TTS Module)

The final step in the interaction flow shows the execution status of text-to-speech:

- **Performance Tracking**: Measures the synthesis duration from when the TTS model request is sent to when the system receives the first audio chunk (First Wave Chunk).
- **Text Verification**: Shows the original input text sent to TTS for conversion to speech, so you can verify the accuracy of the spoken content.
