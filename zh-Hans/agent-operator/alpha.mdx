## Agent运行链路分析

在优化 AI 语音或文本交互体验时，了解每一轮对话背后的系统执行轨迹至关重要。Daisybell 为**非研发人员**（产品经理、交付专家、测试工程师及企业客户）量身打造了 **Agent Analysis Trace（对话链路分析）** 功能。通过可视化、零门槛的诊断，您可以精准分析系统关键运行过程，快速定位交互延迟或异常发生的环节，从而全面提升 Agent 的对话能力。

---

### 1. 功能定位与访问方式

- **产品定位**：用于深入剖析对话流中的系统轨迹。通过透视每一次交互的内部状态，帮助业务定位系统瓶颈或故障环节。
- **访问入口**：Agent Detail对话记录页面中，点击对话明细（Conversation Record）中任意Agent对话气泡下方的 **Latency（耗时）** 标签，系统将从页面右侧展开一个完整的分析抽屉。

### 2. 全局诊断指标 (Global Metrics)

进入 Analysis Trace 后，顶部看板会首先呈现当轮对话的全局核心指标，帮您建立初步的性能快照：

![](/images/zh-Hans/agent-operator/alpha/img-2.png)

- **开始时间 (Start Time)**：记录该轮对话触发的精确时间（格式为 `YYYY-MM-DD HH:MM:SS`）。
- **总耗时 (Total Latency)**：定义为**用户话音结束到 AI 开始发声**的完整跨度（单位：毫秒/ms）。为了提供直观的性能预警，总耗时内置了健康度颜色标识（数值进行 10 位数向上取整）：

  - **延时 $\ge 2000\text{ms}$**：显示为 **黄色**
  - **延时 $\ge 3000\text{ms}$**：显示为 **红色**
- **Token 消耗 (Token Consumption)**：统计当前轮次中，所有大模型（LLM）调用的累计 Token 消耗总量（$\sum\text{LLM}$）。
- **返回状态 (Status)**：明确呈现本轮对话最终的处理状态，标记为 **成功 (Success)** 或 **失败 (Failed)**。

![](/images/zh-Hans/agent-operator/alpha/img-3.png)

### 3. 进程时序泳道图 (Processes Timeline)
为了让耗时组成一目了然，分析抽屉左侧提供了一个多泳道的时间轴图表。系统处理链路上的所有核心服务进程将按执行先后顺序纵向排列：
- **可视化耗时 Bar**：每个进程对应一条彩色耗时条，其起始和结束端点严格对齐实际发生的时间戳。
- **关键路径识别**：时序图中相互重叠、交错或串联的耗时 Bar 最终交织出最长的连续路径，即为您看到的全局 Latency 数据。
- T:数字 代表当前进程所消耗的Token数量

### 4. 核心服务组件深度拆解 (Component Breakdown)

抽屉右侧为各个服务进程的详细控制台，支持展开查看从语音输入到语音输出的完整全栈日志：

#### 4.1 语音识别与完整性检测 (ASR & VAD)

整合了从声音捕获到文本转换的全过程，总耗时由以下三个子板块复合而成：

- **语音活动检测 (VAD)**：提供用户说话的实际后端点时间（Back Endpoint time）以及用户实际说话的时长（Actual duration）。
- **语音转文本 (ASR)**：展示 ASR 模型的识别耗时（Duration）以及最终转译出的文本输出（Output）。
- **话语完整性判断 (Completeness Detection)**：精确记录模型调用时刻（Model Call Time）、模型返回时刻（Model Return Time）以及判断所需的延迟权重，确保系统准确判定用户是否表达完毕。

  ![](/images/zh-Hans/agent-operator/alpha/img-5.png)

#### 4.2 大模型处理逻辑 (LLM Module)

展现 AI 的大脑决策过程，包含核心运行数据与上下文数据流：

- **运行参数**：清晰展示当轮调用的具体模型名称（如 GPT-4o 等）、LLM 进程耗时以及单次请求产生的 Token 消耗数。
- Input：
- Output：显示“Content”中的内容

![](/images/zh-Hans/agent-operator/alpha/img-6.png)

#### 4.3 工具调用 (Tool Calling)

追踪 Agent 调度外部系统或执行特定指令的动作轨迹。系统全面支持多类原生及自定义函数（Function）的执行状态追踪：

- **全类型覆盖**：详细记录包括知识库检索（Knowledge query）、电话转接（Call Transfer / 包含新老版本逻辑）、指令模式切换（Instruction mode）、挂断（Hang up）、语言切换（Language switching）以及业务自定义接口（Customize）在内的各类插件调用。
- **结构化日志**：展示每次 Tool Call 触发的特定函数名（Function_name）、服务耗时、以及标准的 JSON 交互报文（输入参数与返回结果）。

  ![](/images/zh-Hans/agent-operator/alpha/img-7.png)

#### 4.4 语音合成输出 (TTS Module)

交互链路的最后一环，展示文本转语音的最终执行状态：

- **性能追踪**：记录从 TTS 模型发起请求时刻，到系统获取到音频首包（First Wave Chunk）时刻的实际合成耗时。
- **文本核验**：展示驱动 TTS 转化为语音的原始输入文本流（Input Text），便于核对播报内容的准确性。

![](/images/zh-Hans/agent-operator/alpha/img-8.png)
