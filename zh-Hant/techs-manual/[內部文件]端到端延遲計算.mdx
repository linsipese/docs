## 概述

本文件定義我方語音 AI 系統到客戶電話側**各條鏈路的媒體單向時延（OWD）**，給出統一指標口徑、分段計算方法與示意圖。我方系統通過獨立子部署的 **LiveKit**（WebRTC SFU）與 **livekit-sip**（SIP/RTP 閘道）承載語音媒體，出系統後經 **SIP Trunk** 落地到電話網，共覆蓋 6 條路徑（3 條主鏈路 + 3 條轉接路徑）：

- **鏈路一（PSTN 直連）**：livekit-sip → SIP Trunk → PSTN → 客戶手機 / 固網電話。
- **鏈路二（經客戶 PBX）**：livekit-sip → SIP Trunk → 客戶 PBX → 客戶內線話機；或客戶 PBX 出局經 PSTN 呼叫客戶外線電話。
- **鏈路三（PBX 經 PSTN 中轉）**：livekit-sip → SIP Trunk → PSTN → 客戶 PBX → 出局 PSTN → 客戶手機 / 固網電話（客戶 PBX 無法與我方直連時經其公網號碼中轉，兩次穿越 PSTN；轉內線分機場景見轉接③）。
- **轉接人工**：AI 通話中向客服發起第二路呼叫並橋接，客服側路徑分三條——SIP Trunk → 客戶 PBX 內線坐席（直連）；SIP Trunk → PSTN → 客服電話；SIP Trunk → PSTN → 客戶 PBX 公網號碼 → 內線分機（PBX 非直連）。

## 鏈路總覽

三條 AI 對話主鏈路共享我方系統內聯網段（LiveKit SFU、livekit-sip），差異在 SIP Trunk 之後的落地方式；轉接人工複用同一 SIP Trunk 出口，僅呼叫目標不同（直連 PBX 分機號、PSTN 客服號碼，或經 PSTN 落地的客戶 PBX 公網號碼），轉接後媒體時延按客戶側與客服側鏈路分別計算（見第 7 節）。

| 編號 | 媒體路徑 | 適用場景 |
|-|-|-|
| 鏈路一 | 我方系統 → SIP Trunk → PSTN → 客戶手機 / 固網電話 | 未與客戶 PBX 對接，直接撥打公網號碼 |
| 鏈路二 | 我方系統 → SIP Trunk → 客戶 PBX → 內線話機；或 PBX 出局 → PSTN → 客戶外線電話 | 已與客戶完成 PBX 對接（企業專線 / VPN SIP Trunk） |
| 鏈路三 | 我方系統 → SIP Trunk → PSTN → 客戶 PBX 中轉 → PSTN → 客戶手機 / 固網電話（兩次穿越 PSTN） | 客戶 PBX 無法與我方直連，外撥經其公網號碼（DID）中轉出局；轉內線分機場景見轉接③ |
| 轉接① | 我方系統 → SIP Trunk → 客戶 PBX → 內線坐席分機 | 客服坐席註冊在客戶 PBX 分機上，且 PBX 與我方直連 |
| 轉接② | 我方系統 → SIP Trunk → PSTN → 客服電話 | 客服為公網手機 / 固網電話，或不在客戶 PBX 分機內 |
| 轉接③ | 我方系統 → SIP Trunk → PSTN → 客戶 PBX 公網號碼 → 內線坐席分機 | 客服坐席在客戶 PBX 分機上，但 PBX 與我方無直連（含經 IVR 二次撥號） |

## 時延指標定義與通用計算方法

### 指標定義

本文件統一採用**媒體單向時延（One-Way Delay，OWD）**：通話中，一端發出語音幀 → 對端可播放的單向傳播時間，即語音單方向穿過「客戶話機 ↔ 我方系統」或「我方系統 ↔ 客服」整條鏈路的時延。質量目標對標 ITU-T G.114：單向 ≤ 150 ms 為高質量話音。

### 通用計算方法：分段累加

將整條鏈路劃分為標準網段，分別測量或估算各段時延後累加。上、下行媒體路徑對稱（同一批網段反向傳輸），實測不對稱時分別取值：

$$T_{owd} = \sum_{i} t_{i}$$

即各網段時延之和，網段符號見第 4–6 節分段表。統計口徑：各段取 P50 做預算、P95 做上限；抖動緩衝按目標網絡條件取穩態值。

## 鏈路一：SIP Trunk → PSTN → 客戶電話

<whiteboard token="UWm6wXvsGhWhHUbwgbZjA3RApig"></whiteboard>

### 分段時延構成

| 符號 | 網段 / 環節 | 構成説明 | 典型參考值（單向） |
|-|-|-|-|
| t_acc | 客戶接入網 | 固網電話本地網 / 移動空口（4G、5G RAN） | 固網電話 5–30 ms；移動 50–150 ms |
| t_pstn | PSTN | 電訊商承載網傳輸與交換、封包（本地 / 長途 / 國際差異大） | 20–80 ms |
| t_trunk | SIP Trunk | 我方到電訊商 / ITSP 的 IP 網絡（RTT 一半 + 封包） | 專線 10–30 ms；公網 20–80 ms |
| t_tc | 編解碼 / 轉碼 | livekit-sip 內 G.711 ↔ Opus 轉碼（幀長 + 算法時延）；編解碼一致時僅封包 | 轉碼 20–40 ms；不轉碼 5–10 ms |
| t_gw | livekit-sip 閘道 | RTP ↔ WebRTC 適配與轉發處理 | 5–20 ms |
| t_jb | LiveKit / WebRTC | SFU 轉發 + 接收端自適應抖動緩衝（NetEQ） | 30–100 ms |

### 計算公式

鏈路一的單向媒體時延為各網段之和（上下行對稱）：

$$T_{owd}^{A} = t_{acc} + t_{pstn} + t_{trunk} + t_{tc} + t_{gw} + t_{jb}$$

### OWD 參考區間

| 場景 | 單向媒體時延 OWD（參考） |
|-|-|
| 移動客戶（公網 SIP Trunk） | 0.14–0.47 s |
| 固網電話客戶（公網 SIP Trunk） | 0.08–0.35 s |
| 固網電話客戶 + 專線 Trunk（最優組合） | 約 0.09 s |

結論：鏈路一 OWD 參考區間約 **0.08–0.47 s**，主要由接入網（移動空口）、PSTN 承載與轉碼 / 抖動緩衝貢獻；移動客戶場景已明顯超出 ITU-T G.114 的 150 ms 目標，優化方向為專線 Trunk、減少轉碼與收緊抖動緩衝。

## 鏈路二：SIP Trunk → 客戶 PBX → 客戶話機

<whiteboard token="OQlJw2XgGhwQMjbklIijqsVKpwb"></whiteboard>

### 相對鏈路一的增量

鏈路二與鏈路一共享我方系統內段與 SIP Trunk 段，差異在 Trunk 之後：媒體先進入客戶 PBX，再決定落地方式。新增 / 替換的分段如下：

| 符號 | 網段 / 環節 | 構成説明 | 典型參考值（單向） |
|-|-|-|-|
| t_pbx | 客戶 PBX | 信令處理 + 媒體轉發；若 PBX 轉碼或媒體不旁路（媒體經過 PBX 媒體板卡）則顯著增加 | 媒體轉發 2–10 ms；轉碼 20–60 ms |
| t_ext | 內線線路 | PBX 到內線話機的企業內聯網鏈路 | 1–5 ms |
| t_pstn2 | PBX 出局 → PSTN | 僅「PBX 出局呼叫外線」場景存在，等同鏈路一的 PSTN 段 | 20–80 ms |

### 計算公式

設 B1 = PBX 內線落地，B2 = PBX 出局到外線電話，在鏈路一公式基礎上替換尾段：

$$T_{owd}^{B1} = t_{trunk} + t_{pbx} + t_{ext} + t_{tc} + t_{gw} + t_{jb}$$

$$T_{owd}^{B2} = T_{owd}^{B1} + t_{pstn2} + t_{acc}$$

- **B1（內線落地）**：去掉 PSTN 與接入網兩段，換成 PBX 與內線線路，網絡段顯著小於鏈路一；
- **B2（出局外線）**：PSTN 與接入網段照舊，僅增加 PBX 一跳；
- 若客戶 PBX 支持**媒體旁路**（re-INVITE 後媒體不經過 PBX），t_pbx 僅存在於信令階段，通話中按 0 計。

## 鏈路三：SIP Trunk → PSTN → 客戶 PBX → PSTN → 客戶電話（兩次穿越 PSTN）

當客戶 PBX 無法與我方系統直連（不具備專線 / VPN SIP Trunk 條件）時，外撥經客戶 PBX 的公網號碼（DID）中轉落地，再由 PBX 出局撥打客戶電話：媒體**兩次穿越 PSTN**，客戶 PBX 只作中轉，客戶側終端仍是普通手機 / 固網電話，不在 PBX 內部（內線分機場景僅出現在轉接人工的客服側，見轉接③）。該鏈路是三條主鏈路中媒體時延最長的。

<whiteboard token="NNhUwzqAPh5WpcberRsj0UNipoC"></whiteboard>

### 分段時延構成

共享我方系統內段（t_tc、t_gw、t_jb）與 SIP Trunk 段；之後依次為第 1 次 PSTN 穿越 → 客戶 PBX 中轉 → 第 2 次 PSTN 穿越 → 客戶接入網。新增 / 複用分段如下：

| 符號 | 網段 / 環節 | 構成説明 | 典型參考值（單向） |
|-|-|-|-|
| t_pstn3 | 第 1 次 PSTN 穿越 | 我方 Trunk 出局 → 電訊商網間路由 → 客戶 PBX 本地落地（公網號碼 / DID 線路） | 20–90 ms（長途 / 國際取上限） |
| t_pbx | 客戶 PBX 中轉 | 信令處理 + 媒體轉發（複用 5.1 定義） | 媒體轉發 2–10 ms；轉碼 20–60 ms |
| t_pstn2 + t_acc | 第 2 次 PSTN 穿越與客戶接入網 | PBX 出局 → PSTN → 客戶接入網 → 客戶話機（複用 4.1 / 5.1 定義） | 固網電話 25–110 ms；移動 70–230 ms |
| t_did | PBX 呼叫路由 | DID 直達：落地即路由出局；總機模式：自動話務員 IVR 播報 + DTMF 二次撥號後才出局，僅存在於呼叫建立階段 | DID ≈ 0；總機 + IVR 2–10 s |

### 計算公式

$$T_{owd}^{C} = t_{trunk} + t_{pstn3} + t_{pbx} + t_{pstn2} + t_{acc} + t_{tc} + t_{gw} + t_{jb}$$

當兩次 PSTN 穿越時延相近（t_pstn3 ≈ t_pstn2 ≈ t_pstn）時，可由鏈路一直接推導——鏈路三即「鏈路一 + 客戶 PBX 中轉 + 一次額外 PSTN 穿越」：

$$T_{owd}^{C} \approx T_{owd}^{A} + t_{pbx} + t_{pstn}$$

- 相比鏈路一：多出「客戶 PBX 中轉 + 一次額外 PSTN 穿越」兩段，是三條主鏈路中媒體時延最長的；
- 客戶側終端仍是普通手機 / 固網電話；「SIP Trunk → PSTN → 客戶 PBX → 內線分機」的一次穿越場景僅用於轉接人工的客服側（轉接③，見第 7 節）；
- 媒體單向時延參考：固網電話客戶約 **0.11–0.5 s**，移動客戶約 **0.16–0.62 s**；總機模式下的 t_did 隻影響接通前的呼叫建立，不影響接通後的媒體時延，建議採用 DID 直達路由。

## 轉接人工（橋接模式）

### 橋接轉接（本方案唯一方式）

- **橋接轉接**：livekit-sip 保持與客戶的既有通話不變，另向客服發起一路新呼叫，兩路呼叫在我方 LiveKit 房間內橋接；期間客戶可聽等待音或由 AI 繼續播報。轉接後媒體固定經我方橋接，兩側鏈路的媒體時延分別計算後相加，按下節分場景給出。
- **轉接③（PBX 非直連）**：客服側呼叫經 PSTN 撥客戶 PBX 的公網號碼再轉內線分機；DID 直達與總機 IVR 二次撥號隻影響接通前的等待，接通後的媒體時延相同（見下節）。

### 轉接後的媒體時延

橋接轉接下，轉接後通話的單向媒體時延為客戶側鏈路與客服側鏈路之和——客戶側鏈路指客戶到我方系統的一段，客服側鏈路指我方系統到客服的一段；兩側鏈路均已含我方系統內的轉發段，與第 4–6 節各鏈路的 OWD 口徑一致，對話迴路（雙向）為其 2 倍（公式中 cust、agent 分別代表客戶側、客服側鏈路）：

$$T_{owd}^{after} = T_{owd}^{cust} + T_{owd}^{agent}$$

**客戶側鏈路**（客戶 ↔ 我方系統，按第 4–6 節主鏈路場景）：

| 客戶側鏈路場景 | 途經 | 單向媒體 OWD 理論範圍 |
|-|-|-|
| 鏈路一 · 移動客戶 | SIP Trunk → PSTN → 移動空口 | 0.14–0.47 s |
| 鏈路一 · 固網電話客戶 | SIP Trunk → PSTN → 固網電話本地網 | 0.08–0.35 s |
| 鏈路二 · PBX 內線（直連） | SIP Trunk → 客戶 PBX → 內線話機 | 0.05–0.31 s |
| 鏈路二 · PBX 出局外線 | SIP Trunk → 客戶 PBX → PSTN → 客戶話機 | 0.08–0.54 s |
| 鏈路三 · 經 PBX 中轉（固網電話客戶） | SIP Trunk → PSTN → 客戶 PBX 中轉 → PSTN → 固網電話本地網 | 0.11–0.5 s |
| 鏈路三 · 經 PBX 中轉（移動客戶） | SIP Trunk → PSTN → 客戶 PBX 中轉 → PSTN → 移動空口 | 0.16–0.62 s |

**客服側鏈路**（我方系統 ↔ 客服，按轉接路徑）：

| 客服側鏈路場景 | 途經 | 單向媒體 OWD 理論範圍 |
|-|-|-|
| 轉接① · Trunk 直連 PBX 內線坐席 | SIP Trunk → 客戶 PBX → 內線坐席分機 | 0.05–0.31 s |
| 轉接② · PSTN 客服電話（移動） | SIP Trunk → PSTN → 移動空口 | 0.14–0.47 s |
| 轉接② · PSTN 客服電話（固網電話） | SIP Trunk → PSTN → 固網電話本地網 | 0.08–0.35 s |
| 轉接③ · PSTN → PBX 公網號碼 → 內線分機 | SIP Trunk → PSTN → 客戶 PBX → 內線坐席分機 | 0.09–0.4 s（t_did 僅影響呼叫建立，不影響通話中媒體） |

組合上下界：最優組合（鏈路二 PBX 直連內線客戶 + 轉接①）單向約 **0.10–0.62 s**；最差組合（鏈路三移動客戶 + 轉接②移動客服）單向約 **0.30–1.09 s**；全部組合的單向理論區間為 **0.10–1.09 s**，對話迴路（雙向）**0.2–2.2 s**。轉接後為純媒體鏈路，無 AI 處理段，但兩側鏈路疊加後 OWD 已明顯超出 ITU-T G.114 的 150 ms 目標，長鏈路組合（鏈路三 / 移動客戶 + 經 PSTN 客服）需在容量規劃與體驗評估中重點關注。

## 媒體單向時延彙總

| 路徑 / 場景 | 單向媒體時延 OWD（參考） |
|-|-|
| 鏈路一 · 移動客戶 | 0.14–0.47 s |
| 鏈路一 · 固網電話客戶 | 0.08–0.35 s |
| 鏈路二 · PBX 內線落地（直連） | 0.05–0.31 s |
| 鏈路二 · PBX 出局外線 | 0.08–0.54 s |
| 鏈路三 · 經 PBX 中轉，兩次穿越 PSTN（固網電話客戶） | 0.11–0.5 s |
| 鏈路三 · 經 PBX 中轉，兩次穿越 PSTN（移動客戶） | 0.16–0.62 s |
| 轉接後通話 · 橋接兩側鏈路合計 | 0.10–1.09 s（對話迴路約 0.2–2.2 s） |

解讀：各場景 OWD 差異主要由落地路徑決定（0.05–0.62 s），鏈路三（兩次穿越 PSTN + PBX 中轉）最長；轉接統一採用橋接模式，轉接後 OWD 為客戶側與客服側鏈路之和（0.10–1.09 s），長鏈路組合（鏈路三 / 移動客戶 + 經 PSTN 客服）需重點關注；轉接③建議採用 DID 直達分機。

## 實測打點與校準

### 打點位置

| 位置 | 打點內容 | 工具 |
|-|-|-|
| livekit-sip | RTP 首包收發時間戳、RTCP 時延報告（OWD 直接來源）、丟包與抖動 | 組件日誌、tcpdump / Wireshark |
| LiveKit SFU | 房間 join、track 訂閲與首幀到達、轉發與緩衝耗時 | LiveKit telemetry / Prometheus |
| 整鏈路撥測 | 測試呼叫注入參考音頻並從對端回採，測真實迴路時延（÷2 得 OWD） | 撥測腳本 + 打點對齊 |

### 校準流程

1. 對 3 條主鏈路（5 種落地場景）及轉接兩側鏈路組合分別發起撥測（建議每場景不少於 100 次，覆蓋忙時 / 閒時）；
2. 收集各分段時延樣本，輸出 P50 / P95 / P99 分佈；
3. 用實測分佈替換本文各表的「典型參考值」，重算彙總表；
4. 差異較大的分段（如國際 PSTN、弱網移動）單列場景口徑；
5. 據此確定對外 SLA 口徑與告警閾值（如 OWD P95 > 0.5 s 觸發告警）。
