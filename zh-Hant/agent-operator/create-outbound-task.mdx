爲了助力企業高效啓動外撥業務，Daisybell 全新升級外撥任務建立與數據導入。系統能夠自動兼容並糾正各類常見的線索錄入格式，大幅降低因格式不合規導致的導入中斷率。

---

### 1. 新建外撥任務流程 (Create Task)

在 Daisybell 工作臺發起全新的外撥任務時，管理員僅需完成以下三個核心板塊的設定：

#### 1.1 基礎資訊錄入 (Basic Information)

- **任務名稱 (Task Name)**：系統提供必填文字框，並在打開設定彈窗時，設定任務名稱
- **業務Script選擇 (Script)**：用於指派該外撥任務關聯的 AI 話術Script。若當前工作空間內僅存在一個可用Script，系統將預設處於選中狀態，並優先關聯最新建立的Script版本。
- **呼叫優先級 (Priority)**：決定任務在呼叫隊列中的流轉權重，系統預設預設爲 **Normal（普通）** 級別。

![](/images/zh-Hant/agent-operator/create-outbound-task/img-1.png)

#### 1.2 呼叫時間段管理 (Call Time Setting)

您可以精細化控制外撥任務在每週的哪些時間段內允許自動撥出：

- **15分鐘粒度控制**：設定頁面提供了一張覆蓋週日至週一、跨度爲 `08:00 - 20:00` 的可視化時間設定網格，最小設定間隔細化至 15 分鐘，交互界面內置滾動條，預設自動定位至 `08:00` 視圖。
- **快速預設時段 (Select Preset)**：支持一鍵應用系統預設的快捷工作時段。應用預設後，每天的呼叫時間窗口預設設定爲 `08:00` 開始至 `20:00` 結束。

![](/images/zh-Hant/agent-operator/create-outbound-task/img-2.png)

### 2.   外撥線索數據導入與模板規範

![](/images/zh-Hant/agent-operator/create-outbound-task/img-3.png)

系統通過標準化的數據模板，實現了大批量外撥線索的導入。

#### 2.1 外部線索欄位屬性約束 (Fields Specification)

導入文件所支持的欄位（Fields），嚴格對應您提前在 Agent 欄位管理中勾選了“可通過外部導入”選項的自定義欄位：

![](/images/zh-Hant/agent-operator/create-outbound-task/img-4.png)

- **唯一必填項**：在所有導入的列中，**只有“電話號碼 (Phone)”爲強制必填列**，其餘自定義欄位列（如姓名、年齡、性別、備註等）均允許留空或爲空值。
- **物理容量上限**：單次上傳的數據表格最多支持包含 **20 個** 欄位列。如果上傳的文件中超出了 20 列，系統在讀取時將自動忽略超出範圍的列。
- **數據格式約束**：

  - **文字類型**：單單元格最大支持輸入 1,000 個字符。
  - **數字類型**：最高支持保留至 3 位小數。
  - **日期時間類型**：填入的數據需符合標準格式（如 `YYYY-MM-DD HH:mm:ss`）。
  - **布爾類型**：系統會自動將 True 或 False 映射爲對應的業務判斷。
  - **枚舉類型**：填入的文字必須完全命中工作區預設的可用枚舉元素。
  - **字符規範**：爲了確保解析絕對精準，文件內的所有線索數據請儘量使用半角字符錄入。

#### 2.2 下載 Excel 模板

- **結構與順序規範**：**下載的模版是嚴格按照Agent欄位設定生成的，務必使用模版填充對應內容，不要對任何的表頭欄位進行修改**

#### 2.3 上傳限制

系統目前支持且僅支持擴展名爲 **`.xlsx`** 的標準 Excel 文件導入。文件放置到上傳區域後，前端執行基礎校驗，未通過文件將被直接攔截並提示上傳失敗：

- 單個文件的大小不得超過 **50MB**。
- 單個文件內的數據總行數必須**小於 10,000 行**。若表格超出 10,000 行，系統將彈出攔截提示並阻斷上傳流程。

### 3. 數據規範化

爲了徹底解決因客戶錄入習慣差異導致上傳失敗，後端設定了數據規範化（Normalization）處理策略。

#### 3.1 電話號碼規範化

對於強制必填的電話欄位，系統在讀取時會自動執行規範化

- **全/半角數字自動轉換**：自動將輸入的中文或日文全角數字（如 `０１２３...`）統一轉換爲標準的公網半角數字（`0123...`）。
- **高級兩段式撥號兼容**：存儲格式全面兼容兩段式撥號指令，允許號碼中包含 DTMF 控制字符及特殊按鍵符號（如 `+1234<dtmf>2367*#213`）。
- **非法字符強攔截**：如果電話號碼單元格中混入了英文字母（`a-z, A-Z`）或除標準通訊符號外的其他特殊符號（如 `@` 等）
- **唯一性與存在性校驗**：經過規範化清洗後的電話號碼，其最終結果不能爲空，且不允許與當前導入文件內的其他行數據發生重複。

#### 3.2 日期時間欄位多格式識別 (Datetime / Date)

存入系統時統一將其轉換爲標準的 `YYYY-MM-DD HH:mm:ss` 格式

### 4. 數據預覽與行內編輯 (Preview & Edit)

基礎校驗通過後，系統提供數據在線訂正功能

![](/images/zh-Hant/agent-operator/create-outbound-task/img-5.png)

- **文件數據**：包括文件總行數 (Total)、格式正確的合格行數 (Correct) 以及包含錯誤的行數 (Errors)。錯誤行號（例如：`* Row 1, 3 have errors`）。
- **數據狀態視覺高亮**：

  - **錯誤單元格 (Errors)**：凡是包含非法字符、重複號碼、或者因電話爲空等導致校驗失敗的單元格，背景色將自動**變紅**
  - **空值單元格 (Empty)**：對於未填入數據的非必填自定義欄位項，單元格背景色將自動**變黃**
- **數據過濾**：**Filter for rows with empty cells（篩選帶空值行）** 和 **Filter for error rows（篩選錯誤行）**
- **數據編輯**

  - **自適應組件編輯**：點擊操作列的編輯圖標，系統會根據該列對應的底層欄位數據類型（文字、枚舉、布爾、數字等）自適應喚起最符合輸入習慣的行內編輯組件。
  - **記錄增刪**：支持點擊 **Add** 按鈕在首行上方直接插入一個全新的空白行進行手工錄入補齊，或點擊刪除按鈕徹底移除無效或受污染的數據行。
- **確認導入**：只有當整個文件中的所有缺失內容補齊、且錯誤行數徹底歸零（Errors: 0）時，數據纔可提交
