## Agent運行鏈路分析

在優化 AI 語音或文字交互體驗時，瞭解每一輪對話背後的系統執行軌跡至關重要。Daisybell 爲**非研發人員**（產品經理、交付專家、測試工程師及企業客戶）量身打造了 **Agent Analysis Trace（對話鏈路分析）** 功能。通過可視化、零門檻的診斷，您可以精準分析系統關鍵運行過程，快速定位交互延遲或異常發生的環節，從而全面提升 Agent 的對話能力。

---

### 1. 功能定位與訪問方式

- **產品定位**：用於深入剖析對話流中的系統軌跡。通過透視每一次交互的內部狀態，幫助業務定位系統瓶頸或故障環節。
- **訪問入口**：Agent Detail對話記錄頁面中，點擊對話明細（Conversation Record）中任意Agent對話氣泡下方的 **Latency（耗時）** 標籤，系統將從頁面右側展開一個完整的分析抽屜。

### 2. 全局診斷指標 (Global Metrics)

進入 Analysis Trace 後，頂部看板會首先呈現當輪對話的全局核心指標，幫您建立初步的性能快照：

![](/images/zh-Hant/agent-operator/alpha/img-2.png)

- **開始時間 (Start Time)**：記錄該輪對話觸發的精確時間（格式爲 `YYYY-MM-DD HH:MM:SS`）。
- **總耗時 (Total Latency)**：定義爲**用戶話音結束到 AI 開始發聲**的完整跨度（單位：毫秒/ms）。爲了提供直觀的性能預警，總耗時內置了健康度顏色標識（數值進行 10 位數向上取整）：

  - **延時** $\ge 2000\text{ms}$：顯示爲 **黃色**
  - **延時** $\ge 3000\text{ms}$：顯示爲 **紅色**
- **Token 消耗 (Token Consumption)**：統計當前輪次中，所有大模型（LLM）呼叫的累計 Token 消耗總量（$\sum\text{LLM}$）。
- **返回狀態 (Status)**：明確呈現本輪對話最終的處理狀態，標記爲 **成功 (Success)** 或 **失敗 (Failed)**。

![](/images/zh-Hant/agent-operator/alpha/img-3.png)

### 3. 進程時序泳道圖 (Processes Timeline)
爲了讓耗時組成一目瞭然，分析抽屜左側提供了一個多泳道的時間軸圖表。系統處理鏈路上的所有核心服務進程將按執行先後順序縱向排列：
- **可視化耗時 Bar**：每個進程對應一條彩色耗時條，其起始和結束端點嚴格對齊實際發生的時間戳。
- **關鍵路徑識別**：時序圖中相互重疊、交錯或串聯的耗時 Bar 最終交織出最長的連續路徑，即爲您看到的全局 Latency 數據。
- T:數字 代表當前進程所消耗的Token數量

### 4. 核心服務組件深度拆解 (Component Breakdown)

抽屜右側爲各個服務進程的詳細控制檯，支持展開查看從語音輸入到語音輸出的完整全棧日誌：

#### 4.1 語音識別與完整性檢測 (ASR & VAD)

整合了從聲音捕獲到文字轉換的全過程，總耗時由以下三個子板塊複合而成：

- **語音活動檢測 (VAD)**：提供用戶說話的實際後端點時間（Back Endpoint time）以及用戶實際說話的時長（Actual duration）。
- **語音轉文字 (ASR)**：展示 ASR 模型的識別耗時（Duration）以及最終轉譯出的文字輸出（Output）。
- **話語完整性判斷 (Completeness Detection)**：精確記錄模型呼叫時刻（Model Call Time）、模型返回時刻（Model Return Time）以及判斷所需的延遲權重，確保系統準確判定用戶是否表達完畢。

  ![](/images/zh-Hant/agent-operator/alpha/img-5.png)

#### 4.2 大模型處理邏輯 (LLM Module)

展現 AI 的大腦決策過程，包含核心運行數據與上下文數據流：

- **運行參數**：清晰展示當輪呼叫的具體模型名稱（如 GPT-4o 等）、LLM 進程耗時以及單次請求產生的 Token 消耗數。
- Input：
- Output：顯示“Content”中的內容

![](/images/zh-Hant/agent-operator/alpha/img-6.png)

#### 4.3 工具呼叫 (Tool Calling)

追蹤 Agent 調度外部系統或執行特定指令的動作軌跡。系統全面支持多類原生及自定義函數（Function）的執行狀態追蹤：

- **全類型覆蓋**：詳細記錄包括知識庫檢索（Knowledge query）、電話轉接（Call Transfer / 包含新老版本邏輯）、指令模式切換（Instruction mode）、掛斷（Hang up）、語言切換（Language switching）以及業務自定義接口（Customize）在內的各類插件呼叫。
- **結構化日誌**：展示每次 Tool Call 觸發的特定函數名（Function_name）、服務耗時、以及標準的 JSON 交互報文（輸入參數與返回結果）。

  ![](/images/zh-Hant/agent-operator/alpha/img-7.png)

#### 4.4 語音合成輸出 (TTS Module)

交互鏈路的最後一環，展示文字轉語音的最終執行狀態：

- **性能追蹤**：記錄從 TTS 模型發起請求時刻，到系統獲取到音頻首包（First Wave Chunk）時刻的實際合成耗時。
- **文字覈驗**：展示驅動 TTS 轉化爲語音的原始輸入文字流（Input Text），便於覈對播報內容的準確性。

![](/images/zh-Hant/agent-operator/alpha/img-8.png)
