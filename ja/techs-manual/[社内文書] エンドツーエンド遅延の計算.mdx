## 概要

本書では、当社の音声AIシステムから顧客側の電話までの**各経路におけるメディアの片方向遅延（OWD）**を定義し、指標の統一基準、区間ごとの計算方法、構成図を示します。当社システムでは専用サブデプロイの **LiveKit**（WebRTC SFU）および **livekit-sip**（SIP/RTPゲートウェイ）が音声メディアを処理します。システムの外では **SIP Trunk** を経由して電話網に接続します。対象は6経路（主経路3つ、転送経路3つ）です。

- **経路1（PSTN直結）**：livekit-sip → SIP Trunk → PSTN → 顧客の携帯電話／固定電話。
- **経路2（顧客PBX経由）**：livekit-sip → SIP Trunk → 顧客PBX → 顧客内線電話機。または、顧客PBXからPSTN経由で顧客の外線電話に発信。
- **経路3（PBXからPSTN経由で中継）**：livekit-sip → SIP Trunk → PSTN → 顧客PBX → PSTNへ発信 → 顧客の携帯電話／固定電話（顧客PBXと当社が直接接続できない場合、PBXの公衆番号を経由して中継するため、PSTNを2回経由します。内線への転送は「転送③」を参照）。
- **有人対応への転送**：AIとの通話中にオペレーターへの2本目の呼び出しを開始してブリッジします。オペレーター側の経路は3つです。SIP Trunk → 顧客PBXの内線オペレーター（直結）、SIP Trunk → PSTN → オペレーターの電話、SIP Trunk → PSTN → 顧客PBXの公衆番号 → 内線（PBX非直結）。

<callout emoji="💡">

## 経路の全体像

AI対話の主経路3つは、当社システム内の区間（LiveKit SFU、livekit-sip）を共有し、SIP Trunk以降の接続先が異なります。有人対応への転送では同じSIP Trunkの出口を使い、呼び出し先のみが異なります（PBX内線番号への直結、PSTN経由のオペレーター番号、またはPSTN経由で接続する顧客PBXの公衆番号）。転送後のメディア遅延は顧客側とオペレーター側の経路ごとに計算します（第7章参照）。

| 番号 | メディア経路 | 適用シナリオ |
|-|-|-|
| 経路1 | 当社システム → SIP Trunk → PSTN → 顧客の携帯電話／固定電話 | 顧客PBXと連携せず、公衆電話番号へ直接発信 |
| 経路2 | 当社システム → SIP Trunk → 顧客PBX → 内線電話機、またはPBXから発信 → PSTN → 顧客の外線電話 | 顧客PBXとの連携が完了している（専用線／VPN経由のSIP Trunk） |

| 転送① | 当社システム → SIP Trunk → 顧客PBX → 内線オペレーターの内線番号 | オペレーターが顧客PBXの内線に登録され、PBXと当社が直接接続されている |
| 転送② | 当社システム → SIP Trunk → PSTN → オペレーターの電話 | オペレーターが公衆網の携帯電話／固定電話を使用、または顧客PBXの内線を使用していない |
| 転送③ | 当社システム → SIP Trunk → PSTN → 顧客PBXの公衆番号 → 内線オペレーターの内線番号 | オペレーターは顧客PBXの内線にいるが、PBXと当社が直接接続されていない（IVRで内線番号を再入力する場合を含む） |

## 遅延指標の定義と共通の計算方法

### 指標の定義

本書では一貫して**メディア片方向遅延（One-Way Delay、OWD）**を使用します。通話中に一方が音声フレームを送信してから、相手側で再生可能になるまでの片方向の伝送時間を指します。つまり、音声が「顧客電話機 ↔ 当社システム」または「当社システム ↔ オペレーター」の全経路を片方向に通過する際の遅延です。品質目標はITU-T G.114を基準とし、片方向150 ms以下を高品質音声とします。

### 共通の計算方法：区間ごとの合算

経路全体を標準区間に分け、各区間の遅延を実測または推定して合算します。上り・下りのメディア経路が対称（同じ区間を逆向きに伝送）である場合を前提とし、実測で非対称の場合はそれぞれの値を使用します。

$$T_{owd} = \sum_{i} t_{i}$$

各区間の遅延の合計を表します。区間の記号は第4～6章の内訳表を参照してください。統計基準は、予算策定にP50、上限値にP95を使用します。ジッターバッファは想定するネットワーク条件下での定常値を使用します。

## 経路1：SIP Trunk → PSTN → 顧客電話

<whiteboard token="DqW2wzzEmhbc36b9eGejLR50peh"></whiteboard>

### 区間遅延の内訳

| 記号 | 区間／処理 | 内訳 | 代表的な参考値（片方向） |
|-|-|-|-|
| t_acc | 顧客アクセス網 | 固定電話のローカル網／移動通信の無線区間（4G、5G RAN） | 固定電話：5～30 ms、携帯電話：50～150 ms |
| t_pstn | PSTN | 通信事業者のバックボーン網での伝送・交換・パケット化（国内／長距離／国際で大きく異なる） | 20–80 ms |
| t_trunk | SIP Trunk | 当社から通信事業者／ITSPまでのIP網（RTTの半分＋パケット化） | 専用線：10～30 ms、公衆網：20～80 ms |
| t_tc | コーデック／トランスコード | livekit-sip内でG.711 ↔ Opusをトランスコード（フレーム長＋アルゴリズム遅延）。コーデックが一致する場合はパケット化のみ。 | トランスコードあり：20～40 ms、なし：5～10 ms |
| t_gw | livekit-sipゲートウェイ | RTP ↔ WebRTCの変換・転送処理 | 5–20 ms |
| t_jb | LiveKit / WebRTC | SFU転送＋受信側の適応型ジッターバッファ（NetEQ） | 30–100 ms |

### 計算式

経路1の片方向メディア遅延は、各区間の合計です（上り・下り対称の場合）。

$$T_{owd}^{A} = t_{acc} + t_{pstn} + t_{trunk} + t_{tc} + t_{gw} + t_{jb}$$

### OWDの参考範囲

| シナリオ | メディア片方向遅延OWD（参考値） |
|-|-|
| 携帯電話の顧客（公衆網SIP Trunk） | 0.14–0.47 s |
| 固定電話の顧客（公衆網SIP Trunk） | 0.08–0.35 s |
| 固定電話の顧客＋専用線Trunk（最良の組み合わせ） | 約0.09秒 |

結論：経路1のOWD参考範囲は約 **0.08–0.47 s**です。主な要因はアクセス網（携帯電話の無線区間）、PSTNバックボーン、トランスコード／ジッターバッファです。携帯電話の顧客ではITU-T G.114の150 ms目標を大きく超えています。専用線Trunkの利用、トランスコードの削減、ジッターバッファの縮小が改善策です。

## 経路2：SIP Trunk → 顧客PBX → 顧客電話機

<whiteboard token="LppQwALo3hlQjebsehGjUy4ypOg"></whiteboard>

### 経路1からの追加分

経路2は経路1と当社システム内の区間およびSIP Trunk区間を共有します。異なるのはTrunk以降です。メディアはまず顧客PBXに入り、その後の接続先に応じて経路が分かれます。追加または置き換わる区間は次のとおりです。

| 記号 | 区間／処理 | 内訳 | 代表的な参考値（片方向） |
|-|-|-|-|
| t_pbx | 顧客PBX | シグナリング処理＋メディア転送。PBXでトランスコードする場合、またはメディアバイパスを使用しない場合（PBXのメディアボードを経由する場合）は大幅に増加します。 | メディア転送：2～10 ms、トランスコード：20～60 ms |
| t_ext | 内線回線 | PBXから内線電話機までの企業内ネットワーク経路 | 1–5 ms |
| t_pstn2 | PBXから発信 → PSTN | 「PBXから外線へ発信」する場合のみ存在し、経路1のPSTN区間に相当します。 | 20–80 ms |

### 計算式

B1をPBX内線への接続、B2をPBXから外線電話への発信とします。経路1の式の末尾区間を次のように置き換えます。

$$T_{owd}^{B1} = t_{trunk} + t_{pbx} + t_{ext} + t_{tc} + t_{gw} + t_{jb}$$

$$T_{owd}^{B2} = T_{owd}^{B1} + t_{pstn2} + t_{acc}$$

- **B1（内線に接続）**：PSTN区間とアクセス網区間を除き、PBXと内線回線に置き換えます。ネットワーク区間は経路1より大幅に短くなります。
- **B2（外線へ発信）**：PSTN区間とアクセス網区間はそのままで、PBXの1区間のみ追加します。
- 顧客PBXが**メディアバイパス**に対応している場合（re-INVITE後のメディアがPBXを経由しない場合）、t_pbxはシグナリング段階のみに発生し、通話中は0として扱います。

## 経路3：SIP Trunk → PSTN → 顧客PBX → PSTN → 顧客電話（PSTNを2回経由）

顧客PBXと当社システムを直接接続できない場合（専用線／VPN SIP Trunkの条件を満たさない場合）、顧客PBXの公衆番号（DID）を経由して発信を接続し、PBXから顧客の電話へ発信します。この場合、メディアは**PSTNを2回経由します**。顧客PBXは中継のみを担い、顧客側の端末はPBX内線ではなく一般の携帯電話／固定電話です（内線への接続は有人対応への転送先でのみ発生し、「転送③」を参照）。この経路は主経路3つの中でメディア遅延が最も長くなります。

<whiteboard token="U6NLwB6mihxBTPbwbImjkPufpJZ"></whiteboard>

### 区間遅延の内訳

当社システム内の区間（t_tc、t_gw、t_jb）とSIP Trunk区間は共通です。その後、第1回PSTN通過 → 顧客PBXで中継 → 第2回PSTN通過 → 顧客アクセス網の順に進みます。追加または流用する区間は次のとおりです。

| 記号 | 区間／処理 | 内訳 | 代表的な参考値（片方向） |
|-|-|-|-|
| t_pstn3 | 第1回PSTN通過 | 当社Trunkから発信 → 通信事業者間のルーティング → 顧客PBXのローカル網に着信（公衆番号／DID回線） | 20～90 ms（長距離／国際通話では上限値を採用） |
| t_pbx | 顧客PBXで中継 | シグナリング処理＋メディア転送（5.1の定義を流用） | メディア転送：2～10 ms、トランスコード：20～60 ms |
| t_pstn2 + t_acc | 第2回PSTN通過と顧客アクセス網 | PBXから発信 → PSTN → 顧客アクセス網 → 顧客電話機（4.1／5.1の定義を流用） | 固定電話：25～110 ms、携帯電話：70～230 ms |
| t_did | PBXの呼ルーティング | DID直通：着信後すぐに発信先へルーティング。代表番号方式：自動音声応答（IVR）の案内後、DTMFで番号を再入力してから発信。発呼確立段階にのみ発生します。 | DID直通：約0秒、代表番号＋IVR：2～10秒 |

### 計算式

$$T_{owd}^{C} = t_{trunk} + t_{pstn3} + t_{pbx} + t_{pstn2} + t_{acc} + t_{tc} + t_{gw} + t_{jb}$$

2回のPSTN通過遅延がほぼ同じ（t_pstn3 ≈ t_pstn2 ≈ t_pstn）であれば、経路1から直接導出できます。経路3は「経路1＋顧客PBXでの中継＋PSTNの追加通過1回」です。

$$T_{owd}^{C} \approx T_{owd}^{A} + t_{pbx} + t_{pstn}$$

- 経路1と比べ、「顧客PBXでの中継」と「PSTNの追加通過1回」が加わるため、主経路3つの中でメディア遅延が最も長くなります。
- 顧客側の端末は一般の携帯電話／固定電話のままです。「SIP Trunk → PSTN → 顧客PBX → 内線」はPSTNを1回経由する構成で、有人対応への転送先側でのみ使用します（転送③、第7章参照）。
- メディア片方向遅延の参考値：固定電話の顧客は約 **0.11–0.5 s**、携帯電話の顧客は約 **0.16–0.62 s**です。代表番号方式のt_didは接続前の呼確立にのみ影響し、接続後のメディア遅延には影響しません。DID直通ルーティングを推奨します。

## 有人対応への転送（ブリッジ方式）

### ブリッジ転送（本方式で使用する唯一の方式）

- **ブリッジ転送**：livekit-sipは顧客との既存通話を維持したまま、オペレーターに新たな通話を発信し、当社のLiveKitルーム内で2つの通話をブリッジします。その間、顧客には保留音を流すか、AIが案内を続けます。転送後のメディアは必ず当社のブリッジを経由します。両側の経路遅延を個別に計算して合算し、次節でシナリオ別に示します。
- **転送③（PBX非直結）**：オペレーター側からPSTN経由で顧客PBXの公衆番号へ発信し、内線へ転送します。DID直通と代表番号でのIVR再入力は接続前の待ち時間にのみ影響し、接続後のメディア遅延は同じです（次節参照）。

### 転送後のメディア遅延

ブリッジ方式では、転送後の片方向メディア遅延は顧客側経路とオペレーター側経路の合計です。顧客側経路は顧客から当社システムまで、オペレーター側経路は当社システムからオペレーターまでを指します。両経路には当社システム内の転送区間が含まれており、第4～6章と同じOWD基準です。双方向の会話往復遅延はその2倍です（式中のcust、agentはそれぞれ顧客側、オペレーター側の経路を表します）。

$$T_{owd}^{after} = T_{owd}^{cust} + T_{owd}^{agent}$$

**顧客側経路**（顧客 ↔ 当社システム。第4～6章の主経路シナリオに基づく）：

| 顧客側経路のシナリオ | 経由経路 | 片方向メディアOWDの理論範囲 |
|-|-|-|
| 経路1・携帯電話の顧客 | SIP Trunk → PSTN → 携帯電話の無線区間 | 0.14–0.47 s |
| 経路1・固定電話の顧客 | SIP Trunk → PSTN → 固定電話のローカル網 | 0.08–0.35 s |
| 経路2・PBX内線（直結） | SIP Trunk → 顧客PBX → 内線電話機 | 0.05–0.31 s |
| 経路2・PBXから外線へ発信 | SIP Trunk → 顧客PBX → PSTN → 顧客電話機 | 0.08–0.54 s |
| 経路3・PBX経由で中継（固定電話の顧客） | SIP Trunk → PSTN → 顧客PBXで中継 → PSTN → 固定電話のローカル網 | 0.11–0.5 s |
| 経路3・PBX経由で中継（携帯電話の顧客） | SIP Trunk → PSTN → 顧客PBXで中継 → PSTN → 携帯電話の無線区間 | 0.16–0.62 s |

**オペレーター側経路**（当社システム ↔ オペレーター。転送経路に基づく）：

| オペレーター側経路のシナリオ | 経由経路 | 片方向メディアOWDの理論範囲 |
|-|-|-|
| 転送①・Trunk直結のPBX内線オペレーター | SIP Trunk → 顧客PBX → 内線オペレーターの内線番号 | 0.05–0.31 s |
| 転送②・PSTN経由のオペレーター電話（携帯） | SIP Trunk → PSTN → 携帯電話の無線区間 | 0.14–0.47 s |
| 転送②・PSTN経由のオペレーター電話（固定） | SIP Trunk → PSTN → 固定電話のローカル網 | 0.08–0.35 s |
| 転送③・PSTN → PBX公衆番号 → 内線 | SIP Trunk → PSTN → 顧客PBX → 内線オペレーターの内線番号 | 0.09～0.4秒（t_didは呼確立にのみ影響し、通話中のメディアには影響しない） |

組み合わせの上下限：最良の組み合わせ（経路2で顧客PBX内線に直結＋転送①）は片方向約 **0.10–0.62 s**、最悪の組み合わせ（経路3の携帯電話の顧客＋転送②の携帯電話のオペレーター）は片方向約 **0.30–1.09 s**。全組み合わせの片方向理論範囲は **0.10–1.09 s**、会話の往復遅延（双方向）は**0.2–2.2 s**です。転送後はメディアのみの経路で、AI処理区間はありません。ただし両側の経路を合算するとOWDはITU-T G.114の150 ms目標を大きく超えます。長い経路の組み合わせ（経路3／携帯電話の顧客＋PSTN経由のオペレーター）は、容量計画とユーザー体験の評価で重点的に確認してください。

## メディア片方向遅延の一覧

| 経路／シナリオ | メディア片方向遅延OWD（参考値） |
|-|-|
| 経路1・携帯電話の顧客 | 0.14–0.47 s |
| 経路1・固定電話の顧客 | 0.08–0.35 s |
| 経路2・PBX内線に接続（直結） | 0.05–0.31 s |
| 経路2・PBXから外線へ発信 | 0.08–0.54 s |
| 経路3・PBX経由で中継、PSTNを2回経由（固定電話の顧客） | 0.11–0.5 s |
| 経路3・PBX経由で中継、PSTNを2回経由（携帯電話の顧客） | 0.16–0.62 s |
| 転送後の通話・両側の経路をブリッジした合計 | 0.10～1.09秒（会話の往復遅延は約0.2～2.2秒） |

解釈：シナリオごとのOWDの差は主に接続経路によって決まり（0.05～0.62秒）、経路3（PSTNを2回経由し、PBXで中継）が最長です。転送にはブリッジ方式を一律に採用し、転送後のOWDは顧客側とオペレーター側の経路の合計（0.10～1.09秒）となります。長い経路の組み合わせ（経路3／携帯電話の顧客＋PSTN経由のオペレーター）に注意してください。転送③ではDIDから内線への直接ルーティングを推奨します。

## 実測ポイントと校正

### 計測ポイント

### 校正手順

1. 主経路3つ（接続シナリオ5種）と転送時の両側経路の組み合わせごとに通話テストを実施します（各シナリオ100回以上を推奨し、繁忙時・閑散時を網羅）。
2. 各区間の遅延サンプルを収集し、P50／P95／P99の分布を出します。
3. 実測分布で本文各表の「代表的な参考値」を置き換え、一覧を再計算します。
4. 差が大きい区間（国際PSTN、電波状況の悪い携帯回線など）は、個別のシナリオとして基準を定めます。
5. その結果に基づき、対外SLAの基準とアラートしきい値（例：OWDのP95が0.5秒を超えたらアラート）を決定します。
