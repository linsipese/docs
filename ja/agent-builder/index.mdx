## 概要

Daisybell Agent Lab の Agent Builder は、電話および対話業務向けに構造化された Agent を構築するためのエントリーポイントです。企業の Agent 構築担当者、BPO 事業者、顧客導入チームを対象としています。

実際の業務で利用できる Agent には、通常、アイデンティティ、言語、音声、対話フロー、業務知識、データフィールド、変数、ツール呼び出しなど、複数の要素が関係します。Agent Builder では、これらを一連の設定フローにまとめて管理できます。まず Agent の基本情報と業務の入口を定義し、言語、音声、電話リソース、同時実行数などの実行条件を設定します。その後、Script で対話の振る舞いを構成し、Skills、Tools、Knowledge、Fields、Variables を組み合わせて業務フローを設計します。これにより、業務上の役割、対話方針、実行アクション、データ記録の位置付けが明確になります。チームは Agent をモジュール単位で保守でき、管理しにくい長大な Prompt にすべてのロジックを詰め込む必要がありません。

Agent Builder は、構築プロセスを電話業務の実際の制約に合わせることを重視しています。構築担当者は、業務要件に応じて主言語と補助言語を決め、言語ごとに適切な音声機能を設定できます。また、電話回線、発信、転送などのリソース制約も業務設定に組み込めます。対話中の業務ルールは Script と再利用可能な Skills で整理し、検索、転送、ナレッジ検索、言語切り替え、通話終了、カスタム業務アクションなどを実行する場合は、Tools と Function で設定します。ツールの入力、出力、変数マッピングは Agent フィールドに関連付けることができ、注文番号、顧客ランク、処理結果、転送ステータスなどの情報を構造化して記録できます。

ナレッジは、アップロードしてモデルに渡すだけのものではありません。Agent Builder では、ナレッジベースのファイル管理、解析結果の校正、Script との関連付けを組み合わせることで、製品ポリシー、アフターサービス規約、その他の業務資料を保守可能なナレッジ資産として整理できます。さらに、どの業務対話でこれらの内容を呼び出せるかを明確に定義できます。本人確認、認証コードの入力、機密情報の処理が必要なシナリオでは、ツールと変数の設定に検証、再試行、失敗時の処理、データ保護などの業務上の境界を組み込めます。「検証してから実行する」といったルールを、Agent の実行設定に具体的に反映できます。

このように、Agent Builder を使うことで、Agent をデモ用の対話プロトタイプから、企業の業務要件を満たす導入可能な構成へ発展させられます。チームは構築段階で、Agent が何を行うのか、何を根拠に回答するのか、いつツールを呼び出すのか、結果をどう記録するのか、また電話回線、言語、ナレッジ、データの制約下でどのように業務対話を完了するのかを明確にできます。統一された構造化設定により、企業は具体的な業務に合わせて保守可能な Agent を構築し、Agent のルール、ナレッジ、アクション、データ記録を導入後も継続的に管理できます。
